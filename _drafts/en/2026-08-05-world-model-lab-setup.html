Building a World Model Lab from Scratch: A MuJoCo + DreamerV3 Practical Guide

August 5, 2026 · ~15 min read · Tutorial, MuJoCo, DreamerV3, World Models

I've written several theoretical articless about world models — from RSSM math to Sim-to-Real transfer to the VLA comparison. A reader asked: I get the theory, but how do I actually run it?

This article answers that question. I'll walk you through setting up a complete world model experiment environment, step by step from installation to training to visualization. Once you get this running, you'll have a solid foundation for your own experiments.

Our tool stack: MuJoCo (physics simulation) + DreamerV3 (world model) + TensorBoard (visualization). If you need higher-fidelity rendering, you can later swap in Isaac Sim, but MuJoCo is sufficient for getting started.

Tool Selection: Why These Three

MuJoCo: One of the most popular simulation engines in robotics. High physics accuracy, clean API, fast. Open-sourced and free after DeepMind's acquisition in 2021, it's now the de facto standard for robotics learning research. Most world model papers use MuJoCo for experiments.

DreamerV3: A world model algorithm by Danijar Hafner et al., the third generation of the Dreamer series. It uses RSSM (Recurrent State-Space Model) to learn environment dynamics and trains Actor-Critic policies in imagination space. Open-source with clear documentation — the best starting point for learning world models.

TensorBoard: TensorFlow's built-in visualization tool, natively supported by DreamerV3. View training curves, imagination space visualizations, and agent behavior videos in real-time.

Step 1: Environment Setup

System requirements:

  • OS: Linux (Ubuntu 20.04/22.04 recommended) or macOS. Windows users should use WSL2
  • Python: 3.10 or 3.11 (DreamerV3 has version requirements)
  • GPU: Optional but strongly recommended. NVIDIA GPU significantly accelerates training
  • RAM: 16GB+ recommended

Create a new conda environment:

conda create -n worldmodel python=3.11
conda activate worldmodel

Step 2: Install MuJoCo

MuJoCo can now be installed directly via pip — much easier than before:

pip install mujoco

Verify installation:

python -c "import mujoco; print(mujoco.__version__)"

For visual rendering (seeing the robot's 3D view), you'll need a rendering backend. On Linux, use EGL or OSMesa:

# Linux (with GPU)
pip install mujoco[extras]

# Linux (no GPU, headless rendering)
sudo apt-get install libosmesa6-dev
pip install mujoco[extras]

Step 3: Install DreamerV3

Clone the official repository and install dependencies:

git clone https://github.com/danijar/dreamerv3.git
cd dreamerv3
pip install -r requirements.txt
pip install -e .

For MuJoCo environments, install the environment packages:

# MuJoCo control tasks (classic RL benchmark)
pip install dm-control

Verify DreamerV3 imports correctly:

python -c "import dreamerv3; print('DreamerV3 ready!')"

Step 4: Run Your First Experiment

Let's train a world model on a simple MuJoCo task: Walker Walk — teaching a bipedal robot to walk.

python dreamerv3.py \
  --logdir ~/logdir/wm_walker_walk \
  --configs defaults mujoco_control \
  --task dm_control_walker_walk \
  --steps 1e6

Parameters:

  • --logdir: Log and model save path
  • --configs: Preset configurations (defaults + mujoco_control)
  • --task: Specific task name
  • --steps 1e6: Train for 1 million steps (tens of minutes to hours depending on hardware)

To quickly verify the pipeline works, use fewer steps:

python dreamerv3.py \
  --logdir ~/logdir/wm_test \
  --configs defaults mujoco_control \
  --task dm_control_walker_walk \
  --steps 1e4

10K steps takes just a few minutes — enough to verify everything works.

Step 5: Visualize Training

Open another terminal and launch TensorBoard:

tensorboard --logdir ~/logdir/wm_walker_walk --port 6006

Open http://localhost:6006 in your browser. Key metrics to watch:

1. Train Return (train/return): The core metric — cumulative reward in the real environment. Should increase over training.

2. Eval Return (eval/return): Policy performance evaluated in imagination space. Large gap between eval and train return suggests world model accuracy issues.

3. Reconstruction Loss (losses/recon): RSSM's observation reconstruction error. Decreasing values mean the world model is learning environment dynamics.

4. Video Playback: In the Images tab, compare agent behavior in real vs. imagined environments — a direct look at imagination quality.

Step 6: Analyze Training Output

After training, the logdir structure looks like:

~/logdir/wm_walker_walk/
├── events.out.tfevents.*    # TensorBoard logs
├── configs.yaml              # Training config
├── variables.pkl             # Model weights
└── metrics.json              # Metric records

Load metrics.json with Python for analysis:

import json
import matplotlib.pyplot as plt

with open('~/logdir/wm_walker_walk/metrics.json') as f:
    metrics = [json.loads(line) for line in f]

steps = [m['step'] for m in metrics]
returns = [m['eval/return'] for m in metrics]

plt.plot(steps, returns)
plt.xlabel('Training Steps')
plt.ylabel('Eval Return')
plt.title('DreamerV3 on Walker Walk')
plt.savefig('training_curve.png')
plt.show()

Common Issues

Issue 1: MuJoCo rendering error — "GLFW error"

Set environment variable for offscreen rendering:

export MUJOCO_GL=egl     # with GPU
# or
export MUJOCO_GL=osmesa  # without GPU

Issue 2: Training is very slow

Likely causes: no GPU (CPU-only is 10x+ slower), batch size too large, or insufficient environment parallelism. Verify CUDA is properly detected.

Issue 3: Training return not increasing

Try a simpler task first (e.g., reach task). DreamerV3's default hyperparameters are well-tuned for most MuJoCo tasks — usually no need to modify.

Issue 4: Out of memory (OOM)

Reduce replay buffer size in configs: buffer_size=1e5 (default is larger).

Next Step: From MuJoCo to Isaac Sim

MuJoCo is great for algorithm validation, but rendering realism is limited. If you need more realistic visual inputs (e.g., training a robot to recognize objects from camera feeds), you can upgrade to NVIDIA Isaac Sim.

Isaac Sim, built on the Omniverse platform, provides physically accurate simulation with high-fidelity rendering. The API differs from MuJoCo, but DreamerV3's training pipeline is the same — you just need an environment wrapper to adapt Isaac Sim's observation and action interfaces to DreamerV3's expected format.

I'll cover this advanced topic in a future article. For now, get MuJoCo + DreamerV3 running and understand the training pipeline — that's what matters most.

Summary

Today we built a complete world model experiment environment: MuJoCo for physics simulation, DreamerV3 for world model training, TensorBoard for visualization. The whole process from installation to running the first experiment takes about 30-60 minutes (depending on network speed).

Once running, try:

  • Switching to different MuJoCo tasks (cheetah run, hopper stand, humanoid walk)
  • Adjusting hyperparameters and observing imagination quality changes
  • Comparing DreamerV3's sample efficiency with traditional RL (e.g., PPO)
  • Adding language conditioning to explore language-grounded world models

Practice beats theory. Running one experiment teaches you more than reading ten papers.
