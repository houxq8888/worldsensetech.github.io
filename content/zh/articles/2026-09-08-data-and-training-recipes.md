在[前面的行业地图](/zh/articles/2026-09-06-embodied-ai-landscape/)中，我提到过一个越来越明显的趋势：单纯的模型架构差异正在变得不那么容易形成决定性优势，而数据规模、数据多样性和训练 recipe 的重要性正在上升。

这篇文章想把这个问题展开来讲：**具身智能的数据到底难在哪里？不同技术路线对数据的需求有什么不同？训练 recipe 为什么可能比模型选择更关键？**

## 机器人数据为什么和互联网数据不是一回事

大语言模型的成功很大程度上依赖于互联网规模的文本数据——万亿 token 的 pre-training corpus 几乎是公开资源。视觉模型也类似，LAION-5B 等大规模图文数据集为 VLM 提供了基础。

但机器人数据有一个根本性的不同：**它不只是"观察"，而是"交互"。**

一段互联网文本只需要 text；一张互联网图片只需要 pixel。但一条机器人数据通常需要同时包含：多视角视觉观测、本体感觉（关节角度、力矩、末端位姿）、动作指令（action command）、语言指令（如果有）、以及——在很多情况下——奖励信号或任务成功标注。

这意味着：

```
互联网数据：
  observation（文本/图像）→ 规模大、获取成本低

机器人数据：
  observation + action + state + (reward)
  → 规模小、获取成本高、格式不统一
```

这个区别不是细节问题，而是根本性的数据结构差异。它决定了具身智能不能简单地复制 LLM 的"数据 scaling"路线。

## 数据来源的几条路线

目前具身智能的数据来源大致可以分成几类，每一类都有自己的优势和局限。

### 遥操作数据（Teleoperation Data）

最直接的来源是人操控机器人完成任务，记录观测-动作轨迹对。

**优势：** 数据质量高，直接展示"成功完成任务"的行为模式；天然包含人类的操作策略和常识。

**局限：** 采集速度慢、成本高；操作者的技能水平直接影响数据质量；覆盖的任务多样性和环境多样性受限于操作者的时间和想象力。

目前主流的遥操作系统包括 VR 手柄控制、空间鼠标（SpaceMouse）、以及基于视觉的 imitation 系统。一些公司（如 Physical Intelligence、Figure AI）已经建立了大规模的遥操作数据采集流水线。

### 自主采集数据（Autonomous Data）

让机器人在真实或仿真环境中自主探索，收集成功或失败的交互数据。

**优势：** 可以大规模并行采集；不需要人类操作者持续参与。

**局限：** 在真实环境中，自主探索的效率通常很低（随机探索 → 大部分数据无用）；在仿真中，探索效率更高但存在 sim-to-real gap。

RL 训练通常依赖这类数据——agent 在环境中反复试错，收集 on-policy 或 off-policy 的交互数据。

### 仿真数据（Simulation Data）

在仿真环境中生成训练数据。

**优势：** 可以大规模并行、精确控制环境参数、自动标注；可以生成真实环境中难以获取的极端场景数据。

**局限：** sim-to-real gap 仍然存在——仿真中的物理动态（接触力学、摩擦、变形）与真实世界不完全一致。仿真数据的分布和真实数据的分布之间存在 mismatch，直接使用可能导致策略在真实环境中表现退化。

NVIDIA Isaac Sim、MuJoCo 等仿真平台正在被广泛用于生成训练数据。但仿真数据通常需要配合 domain randomization、system identification 或 real-world fine-tuning 来弥合 gap。

### 合成数据：世界模型作为数据生成器

一个越来越重要的方向是：**用训练好的世界模型来生成合成训练数据。**

这在 Dreamer 系列中已经是核心机制——RSSM 在隐空间中"想象"出轨迹，然后在这些想象轨迹上训练 actor-critic 策略。从功能角度看，这就是用世界模型作为数据源。

NVIDIA Cosmos 的定位也包含这个方向——用 world foundation model 生成物理世界预测和合成数据，用于下游策略模型的训练。

**优势：** 不需要额外的真实交互；可以从有限的真实数据中学到世界模型，然后用世界模型"放大"数据量。

**局限：** 合成数据的质量完全取决于世界模型的预测精度。如果世界模型在某些区域预测不准确（通常是分布外区域），合成数据可能引入错误信号，导致策略学到错误的行为模式。

### 互联网预训练数据

VLA 路线的一个独特优势是可以利用互联网规模的预训练数据。RT-2 的核心思路就是把 VLM（在互联网图文数据上预训练）微调为机器人策略——这意味着 VLA 从互联网数据中继承了大量的语义知识和视觉理解能力。

**但互联网数据不能替代机器人交互数据。** 互联网数据提供的是语义先验（"杯子是什么""抓握是什么意思"），而不是操作技能（"怎么稳定地抓住一个装满水的杯子"）。这也是为什么所有 VLA 系统最终都需要机器人数据进行 fine-tuning。

## 不同范式的数据接口

这是容易被忽略但非常重要的一个维度：**不同的技术路线需要的不是同一种数据。**

### VLA 的数据接口

VLA 需要的是 **(observation, instruction, action)** 三元组。

```
输入：视觉观测 + 语言指令
输出：动作（离散 token 或连续向量）
```

VLA 的训练通常分两阶段：先在互联网图文数据上预训练（获得语义能力），再在机器人交互数据上 fine-tune（获得操作能力）。fine-tune 阶段的数据接口是 observation + language → action。

这意味着 VLA 对数据的核心需求是：**高质量的 observation-action 配对，覆盖足够多样的任务和物体。**

### 世界模型的数据接口

世界模型需要的是 **action-conditioned trajectory**：

```
输入：历史观测 + 动作序列
输出：未来观测（和/或 latent state）+ reward
```

Dreamer 的 RSSM 需要完整的 (observation, action, reward, terminal) 序列来学习 latent dynamics。TD-MPC2 需要 (observation, action) 序列来学习 latent consistency 和 reward prediction。

这意味着世界模型对数据的核心需求是：**时间上连贯的、action-annotated 的交互轨迹，需要覆盖足够多样的状态转移。**

### RL 的数据接口

RL 的数据需求取决于 on-policy 还是 off-policy：

- **On-policy**（如 PPO）：需要当前策略产生的数据，数据"新鲜度"很重要
- **Off-policy**（如 SAC）：可以复用历史数据，但需要足够的 diversity 避免 overfitting

从数据角度看，off-policy 方法对 replay buffer 的质量和多样性有更高要求。

### 数据接口不兼容的问题

一个实际中经常遇到的问题是：**不同 embodiment、不同传感器配置、不同动作空间的数据不能直接使用。**

一个在 Franka 机械臂上采集的数据，不能直接用于训练 UR5 的策略——即使任务完全相同。动作空间的维度不同、观测的视角不同、动力学特性不同。

这就是为什么 cross-embodiment data 是一个重要的研究方向——TD-MPC2 通过 task embedding 处理不同 embodiment 的差异，Open X-Embodiment 数据集尝试统一多种机器人的数据格式。但从数据工程角度看，"统一格式"不等于"统一分布"——不同 embodiment 的数据在统计特性上仍然有本质差异。

## 训练 Recipe：数据怎么用可能比数据有多少更重要

"数据量"是一个容易被量化的指标，但在具身智能中，**数据怎么用（training recipe）可能比数据有多少更关键。**

### 数据质量 > 数据数量

这一点在多个工作中被验证过。RT-2 团队发现，少量高质量的机器人演示数据（几千条）加上大规模互联网预训练，往往比大量低质量数据更有效。

直觉上这不难理解：机器人数据中的"噪声"不只是标注错误，还包括操作不流畅、次优策略、传感器噪声等。这些噪声在监督学习 fine-tuning 中会被直接学习，导致策略质量下降。

### 数据多样性与课程学习

另一个关键维度是数据多样性。如果训练数据只覆盖一种杯子、一种光照、一种桌面，策略在遇到新杯子、新光照、新桌面时就会失败。

课程学习（curriculum learning）是一种常用的策略：从简单任务开始训练，逐步增加难度。这在仿真中尤其常见——先让 agent 在简单环境中学习基本技能，然后逐步增加环境复杂度。

### 数据混合策略

VLA 的训练通常涉及多种数据源的混合：互联网图文数据（语义能力）、机器人演示数据（操作技能）、可能还有合成数据（数据增强）。

**这些数据源的混合比例、训练顺序、学习率调度，构成了 training recipe 的核心。** 不同团队在这方面的选择可能非常不同，而这些选择往往对最终性能有显著影响——有时甚至超过模型架构的选择。

### 仿真到真实的适配策略

仿真数据不能直接替代真实数据，但可以通过多种策略来弥合 gap：

- **Domain randomization：** 在仿真中随机化视觉外观、物理参数、环境布局，使策略对变化更鲁棒
- **System identification：** 精确校准仿真器的物理参数，使仿真更接近真实
- **Real-world fine-tuning：** 先在仿真中预训练，再用少量真实数据 fine-tune
- **Domain adaptation：** 学习仿真和真实之间的映射，减少分布差异

这些策略通常不是互斥的，实际系统中往往组合使用。

## 几个值得关注的方向

### 数据 Curation 正在成为一个独立方向

"更多数据"不自动等于"更好性能"。数据筛选、去重、质量评分、多样性保证——这些"数据 curation"工作正在成为一个独立的技术方向。

对于机器人数据来说，curation 的挑战尤其大：如何自动判断一条遥操作轨迹的质量？如何衡量数据集的任务覆盖度？如何检测和处理异常数据？这些问题目前还没有标准化的解决方案。

### Cross-embodiment Data 的机遇与挑战

Open X-Embodiment 等数据集尝试把多种机器人的数据整合在一起。理想情况下，这可以让模型从多种 embodiment 的经验中学习通用的操作原理。

但实际挑战是：不同 embodiment 的数据在动作空间、观测格式、任务分布上都有差异。简单地混合这些数据可能不会带来预期的泛化效果——模型可能花大量容量去"记住"不同 embodiment 的差异，而不是学习共通的操作原理。

TD-MPC2 的 task-conditioned approach 和 π₀ 系列的 cross-embodiment 实验，都在探索如何更有效地利用多 embodiment 数据。

### 数据 Scaling Law：机器人领域是否存在？

LLM 领域已经建立了相对清晰的 scaling law（更多数据 + 更大模型 + 更多计算 → 可预测的性能提升）。机器人领域是否也存在类似的 scaling law？

从目前的情况看，这个问题还没有清晰的答案。原因是：

- 机器人数据的"量"不容易定义（轨迹数？时间步数？任务多样性？embodiment 多样性？）
- 数据质量和多样性的影响可能比纯数据量更大
- 不同任务、不同 embodiment 的 scaling 行为可能完全不同

一个值得验证的假设是：**在数据多样性（而非纯数据量）上 scaling，可能是机器人领域更有效的 scaling 方向。**

## 这意味着什么？

如果把前面几篇文章的线索串起来：

- [世界模型系列](/zh/articles/2026-09-01-world-model-h2-review/)建立了"预测接口"的概念
- [VLA 系列](/zh/articles/2026-09-03-vla-deep-dive/)分析了"语义 + 动作"的接口设计
- [RSSM 演进](/zh/articles/2026-09-04-rssm-beyond/)讨论了不同 latent dynamics 的数据需求
- [行业地图](/zh/articles/2026-09-06-embodied-ai-landscape/)指出数据正在成为关键差异化因素

这篇想说的是：**数据和训练 recipe 可能正在成为具身智能最被低估的竞争壁垒。**

模型架构可以通过论文和开源代码传播；仿真平台正在被少数几个玩家标准化；但**高质量的机器人交互数据、有效的数据 curation 流程、和经过反复调试的 training recipe——这些很难通过一篇论文完整传递。**

这也是为什么我倾向于认为：短期内具身智能的差异化，更多会来自"谁有更好的数据和训练 recipe"，而不是"谁有更大的模型"。
